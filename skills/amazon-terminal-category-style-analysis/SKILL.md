# Amazon 末级类目款式分类分析

把末级类目中的在售、有销量父体 Listing 划分为互斥主款式，并用全量样本与头部样本共同评估每个款式是否值得进入。输出每个款式一个 Excel，并提供跨款式总览。

## 执行原则

- 获取 Amazon 商品、市场和历史趋势数据时，优先使用卖家精灵 MCP；字段不足时依次考虑 Softtime、SIF，再考虑 Amazon 页面或其他公开来源。
- 第三方销量和销售额均标为估算值，并记录站点、节点、数据月份、采集日期、来源和缺失情况。
- 将用户判断、分析假设、数据事实和模型结论分开。用户观点进入假设验证队列，不直接成为分类或商业结论。
- 缺失值保持未知，不以零值或经验值填补。
- 分类、指标、模型和输出均须配置化；类目专属词典不得写入通用计算逻辑。

## 开始前

确认站点、末级类目节点和数据月份。默认使用最近完整自然月；若数据源尚未形成完整上月数据，则回退一个月并记录原因。

首次分析某类目时，先生成候选款式和低置信度样本供复核，再生成正式报告。已有经确认词典时可直接复用，但仍需检查漂移和新增结构。

## 工作流

1. 按[数据与分类流程](references/data-and-classification.md)抓取、清洗、父体去重并形成互斥主款式。
2. 按[指标与评分模型](references/metrics-and-scoring.md)计算市场规模、新品表现、进入难度和机会优先级。
3. 对关键判断执行反证检查：异常单品、品牌驱动、季节性、幸存者偏差、新品短期冲高和历史覆盖不足。
4. 按[工作簿与验证规范](references/workbook-and-validation.md)生成、复算、渲染和校验 Excel。
5. 保存原始数据、排除清单、分类结果、配置、规则版本、输出清单和校验报告。

## 不可混淆的两个结论

- **进入难度**回答“有多难进入”。
- **机会优先级**回答“是否值得优先投入验证资源”。

大市场可以同时具有高优先级和高难度。不得用难度排名代替商业优先级，也不得因市场大而隐去竞争、履约或新品失败风险。

## 交付要求

- 每个已确认款式单独一个工作簿，另提供一个跨款式总览工作簿。
- 每个 ASIN 只能属于一个主款式；辅助属性作为标签，不另行重复计数。
- 产品明细、头部竞品和新品案例尽量嵌入压缩主图，并保留原图 URL 与 Amazon 链接。
- 每项进入建议同时呈现支持证据、反对证据、未验证风险和结论改变条件。
- 新版本写入版本化目录，不覆盖旧报告。
