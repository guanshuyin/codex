# 补货分析

将用户提供的销量、库存、在途、ASIN 和市场数据整理为可复核的补货决策工作簿。保持模型直观，并明确区分源数据、假设和模型输出。

## 开始前

1. 使用电子表格工具完整检查输入工作簿的工作表、表头、合并单元格、公式和日期范围。
2. 读取项目目录中的 `AGENTS.md`，将其作为当前项目已确认业务口径；用户本轮明确说明优先。
3. 核对站点、规划区间、实际／预测月份、库存字段和履约方式。缺少的信息若能从文件可靠推断，可先执行并在结果中标注假设。
4. 需要 Amazon 商品或市场数据时，优先使用可用的卖家精灵、Softtime、SIF MCP；不可用时再使用 Amazon 页面或其他可信来源。外部数据必须记录来源、站点和获取日期。

## 任务路由

- 整理或合并销量表：读取 [references/workbook.md](references/workbook.md)。
- 预测月度需求或日均单量：读取 [references/forecasting.md](references/forecasting.md)。
- 搜集、筛选或计算竞品趋势：读取 [references/competitors.md](references/competitors.md)。
- 分类库存或生成采购／发货计划：读取 [references/inventory.md](references/inventory.md)。
- 处理美国、加拿大、英国或欧洲差异：同时读取 [references/marketplaces.md](references/marketplaces.md)。

只读取当前任务需要的参考文件。完整流程按“基础数据 → 市场与竞品 → 需求 → 分类 → 采购发货 → 校验”执行；若用户要求在某一步停止，则不得提前执行后续步骤。

## 核心约束

- 不从旧文件带入最新版 Sheet1 中不存在的 SKU。
- 不把不可靠竞品强行加入模型；设为 0 权重并重分配给可靠信号。
- 对用户建议进行独立检验，主动指出口径冲突和不合理假设。
- 同一次交付中的 Sheet2、Sheet3、Sheet4 必须使用同一版需求预测。
- 保留源表，输出到项目 `outputs` 下的新文件，除非用户明确要求覆盖。
- 优先使用静态计算值和简单公式，确保 WPS 可打开且无公式错误。
- 交付前进行数值核验与视觉检查，不默认冻结窗格。

## 完成标准

- SKU、ASIN、月份和库存数量可追溯到输入数据。
- 权重之和为 100%，并能解释其数据质量依据。
- 采购和发货满足站点履约、周期、月末日期及装箱规则。
- 结果不存在明显断链、重复 SKU、公式报错或新旧版本错配。
- 最终说明列出输出路径、预测区间、关键假设、被排除的数据源及待业务确认异常。
